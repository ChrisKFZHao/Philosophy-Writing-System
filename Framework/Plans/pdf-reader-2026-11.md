# 对照翻译阅读页与 PDF 提取：调研草稿

- 日期：2026-11-22
- 状态：已定案，按第五节四步推进。第一步（提取层）已完成：`Scripts/pdf-extract.py`，2026-11-22
- 需求：把 PDF 变成原文与译文对照的 HTML 页面，保留版式，显示 agent 批注，用户也能在页面上互动批注；同时去掉对 pdf skill 的依赖，用足够的 PDF 工具降低 token 开销

## 一、现状

1. **pdf skill 是一个空依赖。** `source-intake.md` 第 2 步、`summarize.md`、`evidence-retrieval.md`、`project-conventions.md` 和 README 都要求“用 pdf skill 提取，不准用 `pdftotext`”，但本机没有安装任何 pdf skill，Codex 也没有对应物。实际执行时，模型要么即兴写提取代码，要么直接读 PDF（按页计费，每页同时算文字和图像）。结果不可复现，开销也最大。仓库里找不到禁用 `pdftotext` 的理由。
2. **契约已经有了，实现没有。** `Contracts/evidence-unit.schema.json` 定义了证据单元：定位（页、节、段）、原文片段、来源 SHA-256、提取版本、单元哈希。`evidence-retrieval.md` 要求先复用哈希仍然有效的单元，再重新打开 PDF。但没有任何脚本产出这些单元。
3. 本机环境：Python 3.14，没有 GPU，尚未安装任何 PDF 库。

## 一·五、阅读体验原则（用户，2026-11-22）

用户要的是**连贯、流畅、哲学上准确、不费精力**的阅读。页码改为页边注。由此定下几条设计约束：

1. **段落不被页码切断。** 跨页段落在提取时合并为一段。分页处在正文里只留一个很细的标记，页码放在页边，像学术译本在页边标原书页码那样。印刷页码优先，没有时用 PDF 页序。
2. **译文里的分页标记由翻译时保留。** 原文分页处插一个占位符，如 `⟦p99⟧`，要求翻译时放在对应位置，事后检查占位符的数量和顺序。脚注注号同理。这样译文一侧也能在页边标页码，引用时不必回到原文找页。
3. **以译文为主，原文随取随看。** 默认版式是连续的中文正文，像读一本书；点一段就展开或并排显示原文。另有两栏对照模式，供逐句细读时用。阅读时不必左右来回扫视。
4. **批注不打断阅读。** agent 批注放在页边，正文里只留很淡的标记。术语注只在第一次出现时显示，之后不再重复。论证结构注默认折叠。
5. **翻译以段为单位。** 允许调整句序、拆分长句，让中文读起来顺；但术语、模态强度（may、must、at least）和否定不能动。流畅不能以失真为代价。

## 二、衔接现有流程（初步设计）

核心想法是**一个提取层，多个消费者**。阅读页只是提取层的消费者之一，不单独造轮子。

```
PDF ──pdf-extract.py──> Extract/{stem}/blocks.jsonl ──┬─> ingest：题名页元数据、目录、摘要输入
                         （证据单元，带页码和哈希）      ├─> evidence-retrieval：按页、按短语取段落
                                                        ├─> Citation Gate：核对引文页码
                                                        └─> translate：译文 → 阅读页
```

1. **提取层取代 pdf skill。** 新脚本 `Scripts/pdf-extract.py` 提供 `meta`、`toc`、`text --pages`、`blocks`、`find`、`ocr-needed` 六个子命令。`blocks` 的输出就是证据单元，写到 `Private/Bibliography/Extract/{stem}/`，带来源哈希和提取版本。ingest、reconstruct、review 都改为调用脚本、读取段落块，不再让模型直接读 PDF。
2. **翻译是 `phil:research` 的一个新模式。** 暂名 `translate`；不叫 `read`，避免和 `phil:tutor reading` 混淆。用法：`phil:research translate <KEY> [--pages 12-40 | --chapter 3]`，默认只译用户要读的部分。产出放在 `Private/Bibliography/Reader/{stem}/`：
   - `translation.jsonl`：段落块 id → 译文，记录原文块哈希、模型、术语表版本；原文块变了就标为过期
   - `agent-notes.json`、`user-notes.json`：两类批注分开存放，agent 不改用户批注
   - `reader.html`：由脚本生成，可以随时重建，不进 git
3. **agent 批注的来源都是已有产物。**
   - 术语注：来自术语表（见第 6 条）
   - 论证结构注：来自已有的 Level 1 重构；重构里的前提和结论要挂到段落块 id 上
   - 交叉引用：来自哲学家数据库和 INDEX，例如“此处回应的是 INDEX 中的某篇”
4. **用户批注回流。**
   - `phil:tutor reading` 先读 `user-notes.json`，从用户标出的疑问和高亮开始对话
   - 标签为 `idea` 的批注，经 `idea-ledger.py` 进入想法台账
   - 标签为 `cite` 的批注，变成 `refs.md` 的候选行，并带上页码定位
   - 用户的解读可以充实 Level 2 分析，但不能当作核验证据
5. **Rule 2 的边界。**
   - 译文永远不是来源。手稿引用时以原文段落块的页码为准。
   - 如果手稿直接用我们自己的中译，要注明“笔者据原文译”，并对照原文块核对。
   - 已出版的中译本另立 KEY 引用。
   - Citation Gate 仍然哈希 PDF 本身，不受影响。
6. **一份术语表，两处使用。** 术语表同时服务翻译和 `phil:write` 编辑第三轮的术语检查，这样手稿里的译名和阅读时看到的译名一致。暂定位置：
   - 通用表：`Shared/Glossary/`
   - 项目覆盖：`Private/Projects/{topic}/` 下
7. **存储。** 译文放在 Private 仓库，因为重新生成比存储贵。`reader.html` 和 `Extract/` 是派生物，不进 git。版权方面和范文库一样：只供本机个人学习，不对外分发。

## 三、调研结果

### 3.1 版面提取与对照翻译工具（已完成，关键项已抽查）

- **现成的对照翻译工具只出 PDF。** PDFMathTranslate（pdf2zh）和 BabelDOC 都是 AGPL，都只输出双语 PDF：做不了按段对齐的 HTML，不能单独重译一段，也不支持跨页、跨栏的段落合并（BabelDOC 自己的路线图上这一项还没做）。可以用来做核对参照，不适合做产品底座。Zotero PDF Translate 是阅读器里的划词翻译，同样不能成为流水线的一环。
- **结构提取首选 Marker**（代码 Apache-2.0，2026-11-12 发布 v2.2.0，已核实）：
  - 纯 CPU 可用：`fast` 模式约 23.6 页/秒，`no_ocr` 约 57 页/秒，数据来自它的 README，未在本机实测
  - 自带脚注块识别、页眉页脚去除、页边行号去除、行尾连字符修复
  - 每个块带 PDF 页序和 bbox
  - 缺点：依赖 PyTorch，体积大；脚注不和正文的注号相连；不合并跨页段落；只有 PDF 页序，没有印刷页码；会把斯特方/贝克尔编码当行号删掉
- **备选：** Docling（MIT，JSON 来源信息最干净，约 2 页/秒）；扫描件用 MinerU（许可证 NOASSERTION，附加商业条款）或 olmOCR（需要 NVIDIA 显卡，本机跑不了）。Nougat 已停止维护，pdf2htmlEX 只适合看版面，都不考虑。
- **结论：先提取，再翻译。** 阅读页用自己的版式，要的是结构，不是 PDF 的几何位置。分开做才能控制术语表和提示词，才能按段落哈希缓存、单段重译。BabelDOC 的双语 PDF 只作抽查用的参照。
- **中间格式：** 每块一行 JSON，字段为 id、page、page_label（印刷页码）、type、text、html（保留斜体和上标）、bbox、order、section_path、footnote_refs、source_hash、translation{zh, model, prompt_version, hash, status}。这和证据单元契约基本重合。
- **人文类 PDF 的典型坑：**
  - 脚注要按“页 + 注号”配对；书的尾注每章重新编号，要单独解析
  - 跨页段落按“上段没有句末标点、下段小写开头”拼接，引用时用起始页
  - 连字要做 NFKC 归一化，但不能动 `ß` 和希腊文
  - 印刷页码要在去页眉页脚之前先取出来
  - 缩进的块引用常被并进正文

### 3.2 交互批注层（已完成）

- **不用现成的批注库，写一个小渲染器。**
  - Hypothesis 离不开它的 h 服务器
  - Apache Annotator 已于 2025 年退役，Annotator.js 早已停更
  - Recogito `@recogito/text-annotator`（BSD-3，2026-10 仍有发布，gzip 后 22 KB）是唯一还在维护的完整方案，但它假定只有一个可批注容器，数据格式也是自定义的；侧栏、回复、标签和重新锚定仍要自己写
  - 我们有两栏、段落 id 稳定，自己写反而更小，也能直接产出 W3C 格式
- **数据格式用 W3C Web Annotation。**
  - 每条批注记下段落 id、栏（en 或 zh），以及两种选择器：`TextQuoteSelector`（原文片段加前后各 16–32 字）和 `TextPositionSelector`（只作提示）
  - 回复是另一条批注，target 指向被回复那条的 id
  - 标签用 `purpose: "tagging"` 的 body
- **持久化：本机起一个极小的 Python 服务。**
  - 用标准库，只绑 127.0.0.1，把批注写成 HTML 旁边的 `user-notes.json`，用临时文件加替换的方式原子写入
  - 直接用 `file://` 打开不行：`fetch` 被 CORS 拦下，`localStorage` 的行为没有定义
  - File System Access API 只有 Chrome 和 Edge 支持
  - `localStorage` 只当未保存草稿的缓存，JSON 文件才是真源
  - agent 直接读这个文件
  - 可以做成 `Scripts/reader-serve.py`，一个脚本服务整个 `Reader/` 目录
- **重新锚定，照 Hypothesis 的做法。**
  - 先在原段落、原栏内精确匹配
  - 匹配不上就按编辑距离模糊匹配，打分权重为片段 50%、前缀 20%、后缀 20%、位置 2%
  - 段落 id 没了，再在同一栏全文搜索，不跨栏
  - 低于阈值就标为“未锚定”，放进单独的面板，保留原片段和评论，由用户手动挂回；永不删除，也不悄悄移动
- **agent 批注和用户批注分文件存放**，重新生成 agent 批注不会覆盖用户数据。agent 批注的 id 保持稳定，用户的回复才不会丢。

### 3.3 翻译质量与成本（已完成，价格和三篇论文已抽查）

**什么方法真正有效**

- **按段翻译，并给足上下文。** 每段附上一段原文、约 150 词的滚动摘要，以及本段出现的术语。整篇一次性翻译容易重复，越往后越差（arXiv 2609.12674）。加入摘要和实体译名，COMET 提高 0.4–0.8 分，有用但不大（2503.12152）。DelTA 的实体记忆加摘要，一致性最多提高 4.58 分（2410.08143），适合整本书。
- **术语表注入效果最确定。** 在学术文档上，每一组对比里它都消除了真实的术语错误（2609.35017）。
- **“翻译—反思—润色”主要改善流畅和术语，对忠实度帮助有限而且不稳定。** 润色还会把译文拉向润色模型自己的风格（2605.13368，已核实）。所以润色不能当忠实度检查，反而可能抹平 may 和 must 的区别。
- 多代理的 TransAgents 只在文学文本上验证过，搬到说理性的学术文字上，未必还有收益。

**术语资源**

- 没有可以直接拿来用的英汉哲学术语库。台湾“乐词网”覆盖面广，但不是哲学专库，而且保留版权。SEP 中译站点访问不到。
- 结论：建项目术语表，每行有 sense_id、固定译名、禁用译名、作品既定中译名。
  - 只注入本段出现的词条
  - 第一次出现时括注英文，后续段落通过台账知道已经括注过
  - 译后做确定性检查：译名缺失、两个源词共用一个译名、用了禁用译名，都会被标出来

**成本（300 页书，约 0.21M 输入、0.30M 输出 token/遍）**

| 模型 | 输入/输出（$/M） | 一遍 | 三遍 |
|---|---|---|---|
| Claude Haiku 5.5（≤100K 提示） | 0.10 / 0.50（已核实） | $0.17 | $0.46 |
| Qwen3.8-Flash | 0.15 / 0.47 | $0.17 | $0.50 |
| DeepSeek-V4.1-Flash | 0.30 / 1.20 | $0.42 | $1.18 |
| Claude Sonnet 5.5 | 2 / 10 | $3.42 | $9.18 |
| Claude Opus 5.5 | 4 / 20 | $6.84 | $18.36 |

- 便宜模型起草，强模型只复核被标出的 10–20% 段落：整本书约 $1，比全程 Sonnet 便宜约 88%。
- 其他省钱手段：
  - 系统提示加术语表走提示缓存，命中后的价格只有原价的 1/10 到 1/50
  - 批处理 API 打五折，Anthropic 允许和缓存叠加
  - 参考文献和索引不译，省约 15%
  - 只译打开的章节
  - 按段落哈希缓存，修改 10% 只花 10%

**自动质检**

- 先跑确定性检查：长度比，数字、人名、引文标记是否一一对应，残留的英文，术语合规，否定词和模态词的计数，分页占位符的数量和顺序。
- 本地质量估计模型只用来排序、挑段复核，不当闸门（WMT25 发现自动排名和人工判断会背离）。可选模型：COMET-Kiwi 2.26 GB，许可 CC-BY-NC-SA；MetricX-24 Large 4.9 GB，许可 Apache。纯 CPU 能跑但慢，第一版不装。

**哲学文本的风险，都要提示词规则和检查两头防**

- 术语区分被合并：justification、warrant、reason
- 模态强度被改：may 有认识和道义两种义；at least 不能丢
- 否定词被丢
- 限定语被抹平：arguably、prima facie
- 德文、拉丁文、希腊文引文被翻译
- 有既定中译名的作品被硬译

### 3.4 轻量 PDF 库：取代 pdf skill（已完成，PyPI 安装包已核实）

- **主库：PyMuPDF 1.26.x，锁定 `<2`。**
  - Windows 安装包 18.4 MB，没有依赖，Python 3.14 可用（已核实）
  - 2.x 版是 63 MB，还会连带装上 onnxruntime 等一整套，不要升级
  - 一个库就能覆盖六个子命令：`get_toc`、`get_label`（印刷页码）、`get_xml_metadata`、`get_text("dict")`（每个文字片段的字号和粗体、斜体、上标标记）、`search_for`、`get_pixmap`
  - 许可证是 AGPL。只在本机自用、不分发时，没有任何义务（GNU FAQ）
- **备选：pypdf 加 pdftext**，都是 BSD 或 Apache 许可，两个直接依赖。如果日后要分发，可以换成这一套。
- **扫描件：OCRmyPDF 加 Tesseract 5**，语言用 `eng+deu`，德文花体字加 `deu_latf`。
  - 每页约 2–5 秒，300 页约 15–30 分钟
  - 要另外安装 Tesseract 和 Ghostscript
  - 按需安装，不作为默认依赖
- **token 对比：**
  - 模型直接读 PDF，按 Anthropic 文档，每页 1,500–3,000 个文字 token，另加最多 1,568 个图像 token，合计约 3,100–4,600 个
  - 同一页提取成纯文本约 665 个
  - 相差 5–7 倍；加上段落块缓存，同一页第二次读几乎不花钱
- **启发式规则（自己写，有现成做法可以参考）：**
  - 脚注：字号小于正文主字号，且位于页面下部
  - 页眉页脚：限定在顶部和底部的带状区域，把数字归一化后，在 60% 以上的页面重复出现
  - 跨页段落：按“无句末标点、下段小写开头”拼接，跳过中间的脚注块
  - 页边码：斯特方 `^\d+[a-e]$`、贝克尔 `^\d+[ab]\d+$`、科学院版，先单独提取成页边注，再从正文里去掉
  - 双栏：先在栏缝处切开，再按纵坐标排序
- **当初禁用 `pdftotext` 的可能原因：**
  - Windows 上要另外装 Poppler
  - 不同版本的输出默认值不同，结果不可复现
  - 不给印刷页码、目录和字号，没法做脚注和页眉判断

  这几条理由依然成立，但它们反对的是 `pdftotext`，并不支持“改用 pdf skill”。正确的做法是写一个确定性脚本。

## 五、建议方案

**第一步：提取层（取代 pdf skill）**

- 新增 `Scripts/pdf-extract.py`，基于 pdfminer.six（MIT，纯 Python）。原定的 PyMuPDF 在本机加载不了：Windows 的“智能应用控制”处于强制模式，拦截它没有签名的 `_mupdf.pyd`（错误码 4551）。实测 pdfminer.six 在同一篇论文上空格处理正确（pypdf 会把斜体词和后一个词粘连），能直接分出段落和引文块，16 页约 0.5 秒。子命令为 `meta`、`toc`、`text --pages`、`blocks`、`find`、`ocr-needed`。
- `blocks` 产出证据单元，写到 `Private/Bibliography/Extract/{stem}/blocks.jsonl`，带来源哈希和提取版本。跨页段落合并，页码作为段内分页标记保留，页边码单独成字段。
- 修改 5 处文档，把“用 pdf skill”改成“调用 `pdf-extract.py`”：
  - `source-intake.md` 第 2 步
  - `summarize.md`
  - `evidence-retrieval.md`
  - `project-conventions.md` 的能力查找顺序和 PDF 处理流程
  - README
- 测试用公开 PDF：开放获取期刊（如 Philosophers' Imprint）的文章，以及一本 archive.org 上的扫描旧书。本机没有用户的 PDF。

**第二步：翻译**

- 新增 `Scripts/translate.py`，直接调用用户的模型通道，模型是 deepseek-flash，开思考，预算 2,000 token（见 3.5 的实测）。
- 以段为单位，附上一段原文、滚动摘要，以及本段命中的术语表条目；固定的系统提示走缓存。
- 按段落哈希缓存，只译用户打开的章节。
- 译后做确定性质检：占位符、数字和引文标记、残留英文、术语、否定词和模态词。
- 只把被标出的段落交给强模型修改。是否让修改时开思考，看盲评结果再定。

### 3.5 翻译底座实测（2026-11-22）

用户决定：**翻译用 deepseek-flash，并信任这个第三方模型**。已用一句公有领域的休谟原文测试用户现有的模型通道，结果如下：

- 翻译脚本可以直接调用通道：用户级配置里的 `ANTHROPIC_BASE_URL` 加上 `/messages`，Anthropic 格式，模型名 `deepseek-flash`。凭据从用户级配置读取，不打印。
- **必须关掉思考**，即 `"thinking": {"type": "disabled"}`。不关的话，600 个输出 token 全用在思考上，一个字的译文都没有。关掉后 1.3 秒出译文，65 个英文词只用了 69 个输出 token。
- 分页占位符 `⟦p2⟧` 原样留在了对应位置；术语表里的固定译名和首次括注英文都照做了。
- **提示缓存可用。** 同一份 7.4K token 的系统提示加术语表，第二次请求时 `cache_read_input_tokens` 为 7424，只有 208 个 token 按全价计费。所以每段都带上术语表，成本也很低。
- **关掉思考会不会降低质量？**
  - 文献：通用推理模型开思考，直接翻译时没有稳定收益，常常更差。arXiv 2510.11919：十个语向都没有显著收益，DeepSeek-R1-Distill 不思考反而一直更好。2602.14763：在 WMT24++ 上开推理一致降低质量。2609.21247：推理越长，收益越有限，甚至变差。额外算力在“译后编辑”上更有用（2510.06471，未逐条核对）。
  - 本机实测（5 段 Russell、Mill、Hume）：思考模式的输出 token 是不思考的 5–28 倍（合计 11,783 对 951），其中 80–96% 是思考；耗时是 3–14 倍。
  - opus 盲评，逐句对照原文：
    - 重大错误两组各 1 处。不思考那组给 Russell 的确定断言加了“可能”；思考那组把 Hume 的“唯有……才能”（必要条件）译成了“仅凭……就能”（充分条件）。
    - **次要错误：思考 12 处，不思考 27 处。** 不思考的多数是规则没照做（首次出现时漏了英文括注、没用术语表的译名），以及词义偏移。
    - 不思考那组的 Mill 一段疑似照搬了许宝骙旧译，语体陈旧。
    - 流畅度 19 比 18，偏好 3 比 2，都是思考略优。
  - **结论：在本任务上，关掉思考确实会降低质量**，主要是规则遵循变差。这和文献并不矛盾：我们的提示里有大量明确规则（术语表、首次括注、模态），思考帮的是执行和自查规则，不是翻译本身。样本只有 5 段，属于初步结论。
  - **建议：开思考，但给预算上限**，先试 2,000 token；文献说中等长度的推理最好，过长没有收益（2609.21247）。
    - 全书输出 token 约为不思考的 12 倍。按 DeepSeek 官方价，每书约 $4，仍然便宜；通道的实际价格待确认。
    - 并发 8 路时，一章（约 150 段）大约 6 分钟。
  - 两处重大错误都能被确定性质检抓到：多出来的“可能”会让限定词计数对不上；“alone”和“唯有……才”可以写进模态词表。所以不论开不开思考，质检都要做。
- 走脚本，不走子代理：没有代理的启动开销，可以并发和重试，也能按段落哈希缓存，而且不占主会话的上下文。Codex 或者没有凭据时，退回用子代理。
