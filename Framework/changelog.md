# Framework Changelog

## Unreleased

**Project audit fixes (2026-11-22)**

- Citation Gate: `citation-gate` now reads Hop 1 from `refs.md` (`--key`, `--refs`), blocks `rejected` KEYs and metadata paired to a different KEY, and exits non-zero on BLOCK. `--registered` remains as a legacy flag. Philosopher evidence hash flags must be strictly true.
- Hashing: text artifacts hash with LF line endings, so an autocrlf checkout no longer reports a false stale analysis. PDFs still hash raw.
- Workflow state: approvals record the approved path and go stale when that file changes; `status` is read-only; a citation-closure PASS requires a report; rooted Windows paths are rejected; writes are atomic; neutralizing a high-severity finding requires a reason.
- Idea ledger: status transitions keep an append-only `status_history`, and a corrupt ledger fails cleanly.
- Bibliography: INDEX parsing honors escaped pipes and reports malformed rows instead of reading them by shifted position.
- Philosopher DB: `--person-id` is validated, source-backed approval requires a KEY present in the bibliography INDEX, invalid observation batches are rejected, and approval is idempotent.
- Zotero helper: write tokens prevent duplicate attachments on retry, partial failures keep created keys, proxy resolution no longer forces a hard-coded address, and unsafe stems are rejected.
- Doctor and tests: the stale-phrase scan is case-insensitive, unknown `method.*` IDs in live contracts fail, and private-layer tests skip on a clean clone.
- Contracts and docs: corrected a wrong method ID, `idea-ledger.py` invocations, write-authority wording, removed-command references, and stale counts and versions. `phil-write` no longer mandates stacked connectives and forbids revision by accretion; `phil-review` perspectives must route attributions to source-backed claims.

**Reading page (bilingual reader)**

- New `reader-build.py` builds a self-contained `reader.html` from a source's evidence units, translations, agent notes, and user notes in `Private/Bibliography/Reader/{stem}/`. It reports stale translations, page-marker mismatches between original and translation, note anchors that do not match the text, and unmapped PDF glyphs.
- Template `Framework/Workflow/Templates/Reader/reader.html`: translation first with the original one click away or side by side; printed page numbers in the margin; margin notes beside their anchors (term notes, collapsed argument notes, context notes); a night mode; and user highlights, comments, and `idea` / `cite` tags stored as W3C Web Annotations, exportable as `user-notes.json`. Minimalist serif design.
- Footnotes: `reader-build.py` splits footnote units into single notes by their running numbers and classifies each as substantive, citation-only, acknowledgement, or other (author–year references, `see`/`cf.` pointers, and stock phrases do not count as content; `reader.json` can override). The page shows only substantive note markers and previews a note on hover; a 引注 switch reveals the rest.
- `pdf-extract.py` (version 4): a small-type box at the foot of a page that follows a body line ending in a colon (or an introducing “as”) and is at least two lines or 80 characters long is a block quotation, not a footnote.
- Piloted on section I of Srinivasan 2018 (pp. 123–127): 26 units translated by deepseek-flash with the project glossary, 13 notes drawn from the existing analysis. Two translators rendered *anger* differently, so a cross-unit term check is needed before `translate.py` ships.

**Export: talk handouts and slides**

- `phil:write export` turns finished material into a talk handout, a slide deck, or a Word file. The model writes one Markdown content file under the rules in `references/export.md`, which draw on published advice for philosophy talks. `render-output.py` renders and checks it.
- `render-output.py` uses Pandoc for pptx, docx, and HTML, and a headless Edge or Chrome to print PDF, so no LaTeX is needed. It turns `[@KEY, page]` into （作者，年份：页码）, refuses KEYs missing from `refs.md`, appends 参考文献 to handouts, verifies quotations against the manuscript or evidence units, and reports slide density, missing speaker notes, slide count against talk length, and handout pages.
- Templates in `Shared/Format/`: `handout.css`, `slides.css`, and `reference.pptx` / `reference.docx` generated by `render-output.py make-reference`.
- Piloted on rawlsian-ai: a two-page handout and a 17-slide deck for a 20-minute talk. The first content draft needed fidelity fixes (one premise overstated, one attribution too broad, one conditional turned into an assertion) and many cut disclaimers, which led to tighter export rules.

**PDF extraction replaces the pdf skill**

- New script `pdf-extract.py` with subcommands `meta`, `toc`, `text`, `blocks`, `find`, and `ocr-needed`. `blocks` writes evidence units to `Private/Bibliography/Extract/{stem}/` with source hash and extraction version, and a cache hit costs only a hash. It drops running heads and page numbers, tags footnotes, headings, and block quotes, orders two-column pages, joins hyphenated and CJK line breaks, merges paragraphs across pages while recording each page break, and attaches Stephanus and Bekker margin numbers.
- Running heads are detected per page parity as well as overall (journals alternate author and title), printed page numbers found in the head or foot replace PDF page order as labels when the PDF defines none, and lines with wide justified word spacing are no longer split (`char_margin` 3.0). Small type with body text below it is a quotation, not a footnote. Extraction version 2.
- Scanned pages: `pdf-extract.py ocr-setup` installs tesseract.js 7 (WASM, runs under the signed node.exe) and language data in `%LOCALAPPDATA%\phil-ocr` without admin rights; `ocr` renders pages with the built-in Windows PDF renderer (`pdf-render.ps1`), recognizes them (`ocr-pages.js`), and writes `ocr.jsonl` beside the evidence units without touching the PDF. Pages without a text layer then read the OCR lines, split into paragraphs by first-line indent, with folios dropped, footnotes told apart by line height, and digit-for-I misreads in roman numerals corrected. Units from OCR pages carry `layout.ocr`. Tested on six pages of a 588-page scan (mean confidence 94.5, about 2 s per page). Extraction version 3; output for text-layer PDFs is unchanged.
- It uses pdfminer.six (MIT, pure Python). PyMuPDF was planned but cannot load where Windows Smart App Control blocks unsigned DLLs.
- `source-intake`, `summarize`, `evidence-retrieval`, the ingest mode, the conventions file, and the README now call the script instead of the pdf skill, which was never installed. The evidence-unit contract gains an optional `layout` object.

**File conventions**

- Source PDFs in `Private/Bibliography/PDF/` are now tracked in the private repository (`!Bibliography/PDF/*.pdf` in `Private/.gitignore`). Extraction caches, compiled LaTeX, and rendered exports stay ignored. `source-intake` renames tracked PDFs with `git mv` and commits new PDFs with their INDEX rows.
- Intermediate and generated files are Markdown. New conception notes, outlines, review reports, pipeline prose, summaries, and analyses use `.md`. Manuscripts (`-draft.txt`, `-v{N}.txt`) stay plain text. `bibliography-scan.py` and `content-doctor.py` still accept legacy `.summary.txt` files.

**Method execution cards (pilot)**

- `analogy-check`, `parity-check`, `intuition-pump`, and `contextualize` now load as execution cards of about 10 KB each. The complete original of each method is preserved as `references/<slug>-full.md` and loads only when the card does not settle a live ambiguity.
- Adopted after a blinded comparison on public-domain texts. Across ten judgments the cards and the full methods each won five (233 versus 230 points), while the card runs used about 23% fewer tokens. `methodology` lost both of its judgments by one point and keeps its full text until its card is revised.

**Section pipeline (default for draft mode)**

- `phil:write` draft mode now drafts each section with a section pipeline; `PROJECT.md` can set `drafting: classic` to keep the old procedure. The pipeline runs argument sheet (user gate), compose in a fresh subagent, `prose-lint.py`, a three-pass editor, a cold reader, and a comparison step that sends only prose-caused findings back to the editor. Definitions are in `Framework/Plugin/skills/write/references/section-pipeline.md`.
- New script `prose-lint.py` reports Chinese prose patterns. It flags long sentences, 的 chains, light verbs, stock phrases, hedge stacks, runs of three or more sentences with no logical link (`bare-run`), section signpost formulas, and disclaimers. It never scores or rewrites the text.
- Adopted after a two-round pilot. In the first blind round on three real sections, the user scored it 58 to 57 against the classic procedure and preferred it in one section and the classic draft in another. The losing draft read as a list of bare assertions: 48% of its sentences were in link-free runs, against 17% for the classic draft. The compose, edit, argument-sheet, and cold-read briefs were revised so that sentence relations are written out, recap and roadmap formulas between sections are dropped, and each disclaimer must name the misreading it blocks. In the second round, on s1 and s2, link-free runs fell to 0% and 22% and every claim was recovered. Most of the remaining defensive tone came from disclaimer lines in the argument sheets, so the sheet gate now requires a disclaimer review: each 界限 or "is not" line is listed with the misreading it blocks, and unneeded ones are proposed for cutting. The user reviewed the second round and accepted it.

**One plugin and one root guide**

- Public skills now live in a single plugin tree, `Framework/Plugin/`, with manifests for Claude Code and Codex. `/phil:research`, `/phil:tutor`, `/phil:write`, `/phil:review`, and `/phil:full` come from the plugin namespace. A host that has not loaded the plugin can read `Framework/Plugin/skills/<name>/SKILL.md` directly.
- Removed the generated `.claude/skills`, `.claude/commands`, `.claude/rules`, `.agents/skills`, root `CLAUDE.md`, and all nested bridges in `Private/`. Private projects keep a generated `AGENTS.md` pointer.
- `AGENTS.md` is now the only root guide and is hand-maintained (about 6,400 characters, down from about 58,000 always-loaded characters). Detailed conventions moved to `Framework/Workflow/References/project-conventions.md`.
- `build-adapters.py` now generates only the plugin manifests, marketplace files, and private pointers. It never deletes files, and `--check` fails if a legacy adapter path exists.
- Skill descriptions now lead with the use case and include Chinese trigger terms.

**Session-scoped cost-aware delegation**

- Removed static role-to-model mappings, including the former generated high-tier Claude mapping. Generated roles now inherit the host session model.
- Replaced the unimplemented routing design with a session-scoped prompt policy. The user authorizes one lower-cost host candidate once per session; no catalog, telemetry, pricing estimate, or automatic host task creation is stored or inferred.
- Only repeatable, independent, read-only, non-interactive candidate work may use that authorization. Parent tasks validate candidates before writes, verified claims, or Citation Gate use; writing, review, artifact changes, user dialogue, and orchestration retain the current session model.

## v0.4.4-alpha — 2026-07-14

**`/phil:ingest` supports monographs and edited collections** (finer-grained summaries + per-paper Zotero items)

- **Document-type detection** (Step 2): `paper` / `monograph` / `collection`, decided by whether chapters are independent, separately-citable works — not by author count (a single author's self-collection is a collection). Books also get ISBN + table-of-contents extraction (Rule 2, from the PDF)
- **Chapter-level summaries** (Step 6): a monograph's `.summary.txt` carries per-chapter segments (`chapters[]`, ~150–300 chars); an edited collection yields a volume summary **plus one independent summary file per member paper** (chapter-level stem, its own topics, a `container` back-link)
- **Per-paper INDEX rows** (Step 5): a collection registers a volume row (KEY `EDITOR-TITLE`) plus one row per member paper (KEY `AUTHOR-TITLE`); member rows point at the shared volume PDF + page range + `in <volume-KEY>`, so each member is independently citable through the two-hop Citation Gate. One physical PDF per volume — never split or copied
- **Two-tier Zotero gate** (Step 8): DOI for papers, **ISBN for books** (`zotero_add_by_isbn`). A collection additionally gets one `bookSection` per member paper (`zotero_add_by_bibtex` `@incollection`), and the volume PDF is linked to the book item + every bookSection in one batch POST. `zotero_add_by_isbn` has no `attach_mode` → first book ingestion verifies no stored copy; Open Library / Google Books metadata cross-check is mandatory (less reliable than CrossRef)
- **`zotero-attach-linked.py` batch mode**: `--parents KEY1,KEY2,…` attaches one stem to many parents in a single POST (auto-splits at Zotero's 50-item cap); single-parent usage unchanged
- Schema: `summary-schema.json` gains `collection` source type, optional `chapters[]` (monograph) and `container` (collection member)
